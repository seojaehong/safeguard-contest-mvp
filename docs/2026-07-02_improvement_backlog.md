## 배치 1 — 시연 임팩트 (본선 직결, 각각 소규모, SDD 즉시 실행 가능)

### T1. inferScenario 업종 오분류 수정 [효과 大 / 난이도 小]
- 증상: "상하차" 키워드가 물류업으로 강매칭 → "안산 **제조공장** 용접"이 업종=물류업, 작업명="상하차 및 피킹"으로 오분류. 문서 기본정보 헤더에 그대로 노출 (심사위원 눈에 띄는 결함).
- 수정: lib/search.ts(또는 시나리오 추론 모듈)의 업종 키워드 우선순위 — 명시 업종 단어(제조공장/공장/건설현장/물류센터)가 작업 동사(상하차/피킹)보다 우선. 회귀 테스트: 시연 질문 → companyType=제조업.
- **검증으로 확인된 전파 피해**: workPlan에 "랙 피킹" 혼입+용접 누락, tbmBriefing 위험요인 3종 전부 물류형(용접 화재 누락), 교육기록 "물류센터" 교육명+용접 교육 전무, 회사명 "안산"(지명) 오추출. → 단일 수정으로 문서 4종이 동시에 좋아지는 최대 레버리지.
- AC: vitest에 시나리오 추론 케이스 3건+ (제조/건설/물류 각 1), 시연 질문 실검증.

### T2. 환각 값 가드 — 기본정보 빈칸 강제 [효과 大 / 난이도 小]
- 증상: 위험성평가 기본정보에 지어낸 값("회사명: (주)OO제조", "작업 책임자: 김철수", "작업 일자: 2024년 7월 26일") 관찰됨.
- 수정: persona() 원칙에 추가 — "회사명·현장명·인원 등은 [현장 시나리오] 값만 사용. 시나리오에 없는 이름·날짜·전화번호·주소는 지어내지 말고 '____' 또는 '현장 확인 필요'로 표기."
- AC: 프롬프트 반영 + prod/로컬 생성 결과에서 시나리오 외 고유명사 부재 확인.

### T3. foreign 프롬프트 길이 스펙 모순 수정 [난이도 小]
- 증상: "헤더당 800~1500자 × 3개 언어" vs "전체 4500~7000자"가 수학적으로 모순 (Opus가 발견). 모델이 스펙을 임의 해석.
- 수정: "한국어 800~1500자, 영어·베트남어는 동등 내용(글자수 무관), 전체 12,000자 이내" 식으로 일관화.
- AC: 프롬프트 문구 수정 + foreign 생성 1회 실검증(3헤더+5항목 유지).

### T4. tbmLog 등 코드펜스 파스 실패 관대화 [난이도 小]
- 증상: 로그에 `[AI tbmLog] parse failed. head=```json` — 모델이 펜스로 감싸면 1차 파스 실패→재시도(표준 문서라 2회 허용이지만 시간 낭비).
