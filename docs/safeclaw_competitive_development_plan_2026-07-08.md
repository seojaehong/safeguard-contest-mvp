# SafeClaw 경쟁 대비 개선 개발계획서

작성일: 2026-07-08

## 1. 결론

오늘 멘토링 피드백의 핵심은 타 서비스 대비 특장점이 약하다는 점이다. 현재 SafeClaw는 한 줄 입력으로 위험성평가, TBM, 안전교육, 외국인 안내문, 전파 메시지를 생성하는 서비스로 보이지만, 이 문장은 이미 시장에 있는 AI 위험성평가, 모바일 TBM, 중대재해 대응 SaaS와 크게 다르지 않다.

SafeClaw의 차별화 방향은 "AI 문서 생성기"가 아니라 "근거 있는 문서팩을 만들고, 제출 전 검수하고, 현장 전파와 증빙 파일철까지 닫는 안전관리 작업공간"이어야 한다.

## 3. 유사 서비스 리서치

### 3.1 KRAS

고용노동부와 안전보건공단은 2025-01-02에 중소규모 기업도 서류 부담 없이 위험성평가를 할 수 있도록 KRAS 개편을 공개했다. 자료모음집과 온라인·모바일 흐름을 함께 제공한다.

출처: https://www.moel.go.kr/news/enews/report/enewsView.do?news_seq=17418

SafeClaw 대비 의미:

- 무료 공공 기준과 정면 경쟁하면 이기기 어렵다.
- SafeClaw는 KRAS를 대체하기보다, KRAS식 위험성평가 결과를 TBM, 교육, 외국인 안내, 증빙 파일철로 이어주는 "실행 보강층"으로 포지셔닝해야 한다.

### 3.2 카스웍스

카스웍스는 위험성평가를 중심으로 TBM, 안전교육, 근로자, 점검, 사고대장을 연결하는 통합 안전관리 플랫폼을 강조한다. 공정별 템플릿, TBM 자동 반영, 서명, 결재, 이력 보존을 주요 가치로 내세운다.

출처: https://www.caas.works/blog/6927b4f03b421b4425ca5f98

SafeClaw 대비 의미:

- 모바일 운영, 결재, 현장 이력은 이미 강한 경쟁자가 있다.
- SafeClaw가 같은 방향으로만 가면 "작은 카스웍스"가 된다.
- 대신 SafeClaw는 "공공 근거와 생성형 AI 문서팩을 현장 실행 기록으로 바꾸는 경량 코파일럿"으로 좁혀야 한다.

### 3.3 켐토피아 모바일 TBM

켐토피아는 웹과 모바일을 통한 위험성평가 PDCA 관리, 현장 작업자 TBM 수행, 작업중지 요청, SOS, 숙지 여부 확인, 보호구 안내 등을 제공한다.

출처: https://www.chemtopia.net/ko/safety/solution-a-3

SafeClaw 대비 의미:

- 현장 모바일 기능만으로는 차별화가 어렵다.
- SafeClaw의 다국어 안내는 단순 번역이 아니라 "작업자 이해 확인"과 "전파 증빙"으로 연결되어야 경쟁력이 생긴다.

### 3.4 무사퇴근 AI 위험성평가

무사퇴근은 작업 정보를 입력하면 과거 산업재해 사례 기반으로 위험 요소를 분석하고, 관련 법령에 따른 안전조치를 제안하며, 위험성평가 문서를 생성하는 AI 기능을 출시했다고 소개된다.

출처: https://www.mk.co.kr/news/business/11329469

SafeClaw 대비 의미:

- "AI가 위험요인과 법령을 찾아 문서 생성"은 이미 차별점이 아니다.
- SafeClaw는 AI 결과를 다시 검수하는 QA 계층, 미검증 조문 제거, 누락 조치 탐지, 증빙 매핑을 전면 차별점으로 삼아야 한다.

### 3.5 AI Riska

AI Riska는 사진분석, 위험성평가, 안전보건계획서, 안전보건관리비 계획서, TBM 일지를 작성 화면으로 나누어 제공한다.

출처: https://www.ai-riska.com/

SafeClaw 대비 의미:

- "안전관리 서류 자동화" 자체는 이미 일반화되고 있다.
- SafeClaw는 사진분석보다는 공공데이터, 법령, KOSHA, 기상, 교육, 다국어 전파를 연결하는 근거 기반 문서팩에 집중하는 편이 낫다.

### 3.6 함께 플랫폼 / TBM AI

함께 플랫폼 자료는 중대재해처벌법(중대 사고 예방 의무와 책임을 정한 법)과 산업안전보건법 기준 반영, 자동 이행 가이드, 사진과 데이터 기반 증거 보관, 전자서명과 버전 관리를 강조한다.

출처: https://www.cak.or.kr/download.do?uuid=e4a2fd6a-2f8c-4f6d-8864-03626a28aee2.pdf

SafeClaw 대비 의미:

- "법적 대응", "증거 확보", "프로세스 안내"도 이미 경쟁 문구다.
- SafeClaw는 법적 완전 대응을 약속하기보다, "제출 전 점검", "누락 보완", "근거 위치 표시"처럼 검증 가능한 보조 기능을 말해야 신뢰가 높다.

## 4. 경쟁 대비 포지셔닝

### 버려야 할 포지션

- AI 위험성평가 자동 작성 서비스
- 모바일 TBM 앱
- 중대재해처벌법 대응 SaaS
- 안전관리자 대체 서비스
- 범용 안전관리 올인원 플랫폼

이 포지션들은 이미 경쟁자가 있거나, 초기 MVP가 감당하기 어렵거나, 법적 책임을 과하게 암시한다.

### 가져가야 할 포지션

SafeClaw는 "작업 전 10분 안에 공공 근거 기반 안전 문서팩을 만들고, 제출 전 누락을 검수하고, 작업자 언어로 전파한 뒤 증빙으로 남기는 현장 안전문서 코파일럿"이어야 한다.

핵심 차별 문장:

> SafeClaw는 위험성평가 하나를 쓰는 도구가 아니라, 오늘 작업을 근거 있는 문서팩, 제출 전 검수, 다국어 전파, 증빙 파일철까지 닫는 작업 전 안전관리 루프입니다.

## 5. SafeClaw만의 특장점으로 재정의할 기능

### 5.1 제출 전 검수 엔진

현재 내부 MCP 문서에는 `qa_review_docpack`, `validate_safety_citations`, `sanitize_emergency_contacts`, `get_evidence_mapping`이 존재한다. 이 기능은 경쟁 서비스의 "AI가 써줌"과 다르게 "AI가 쓴 문서를 다시 검수함"이라는 차별점이 된다.

개발 과제:

- 문서 생성 후 자동으로 `제출 전 점검` 패널 표시
- 누락된 안전조치, 미검증 조문, 허위 연락처, 증빙 슬롯 누락을 분리 표시
- "법적 인증"이 아니라 "검토 필요 항목"으로 표현

### 5.2 증빙 파일철 자동 구성

중대재해처벌법 시행령 제4조(안전보건관리체계 구축 의무의 구체 항목)에 맞춰 문서팩을 증빙 항목으로 묶는 기능은 강한 차별점이 될 수 있다.

개발 과제:

- 위험성평가, TBM, 안전교육, 사진, 전파 로그를 시행령 제4조 항목별 증빙으로 매핑
- 각 항목에 `충족`, `보완 필요`, `현장 확인 필요` 상태 부여
- 다운로드 가능한 제출 전 파일철 목차 생성

### 5.3 공공 근거 출처 표시

경쟁 서비스는 "법령 기반"을 말하지만, SafeClaw는 문서 문장 단위로 산업안전보건법, KOSHA 자료, 기상청, 고용24, 유사 재해사례를 연결하는 쪽이 적합하다.

개발 과제:

- 각 문서 문단에 근거 태그 표시
- 근거 없음, 템플릿 근거, 실시간 API 근거를 구분
- 라이브 API가 실패하면 문서 상단에 결손 배지 표시

### 5.4 다국어 전파와 이해 확인

다국어 안내는 번역 기능으로 보이면 약하다. 외국인 작업자에게 쉬운 문장으로 전달하고, 이해 확인까지 남기는 구조여야 한다.

개발 과제:

- 작업자별 언어, 쉬운 한국어, 그림/픽토그램 안내 생성
- 문자/메일/카카오/밴드 전파 로그 저장
- "읽음", "확인", "질문 있음" 같은 최소 확인 상태 수집
- TBM 기록과 작업자 이해 확인을 같은 문서팩에 귀속

### 5.5 에이전트 네이티브 도구 계층

SafeClaw는 MCP 서버를 통해 외부 에이전트가 `generate_reviewed_safety_docpack` 같은 도구를 호출할 수 있다. 일반 SaaS 화면보다 더 개발자/AI 생태계 친화적인 차별점이다.

개발 과제:

- `/settings/ai-connect`를 데모 시나리오에 포함
- 외부 에이전트가 문서팩 생성, 검수, 근거 조회를 호출하는 장면을 시연
- A2A Agent Card는 "로드맵"이 아니라 실제 호출 가능한 MCP 도구와 연결해서 설명

## 6. 기존 계획서 보완

기존 계획서의 4대 방향은 유지하되, 순서를 바꿔야 한다.

### 기존 방향

- SIF 기반 재해분류
- 법 기준 정합성
- 공공 API 장애 대응
- 업종 특화 모듈

### 보완 방향

1. 경쟁 차별 메시지: 생성이 아니라 검수와 증빙까지 닫는 루프
2. 제출 전 검수 엔진: AI 결과의 누락과 환각을 잡는 품질 계층
3. 증빙 파일철: 시행령 제4조 항목별 evidence map
4. 다국어 전파: 외국인 작업자 이해 확인까지 기록
5. SIF 분류: 위험도 예측보다 문서팩 누락 탐지와 우선순위 배정에 먼저 사용
6. 업종 특화: 물류/지게차 한 가지 시나리오부터 완성도 있게 구현

## 7. 개발 로드맵

### Phase 0: 발표와 데모 메시지 정리

목표:

- 심사자가 SafeClaw를 "또 다른 AI 위험성평가"로 보지 않게 만든다.

작업:

- 랜딩 첫 화면 문구를 `문서팩 생성`에서 `생성 + 제출 전 검수 + 전파 + 증빙`으로 변경
- `/why` 또는 `/trust`에 경쟁 대비 표 추가
- 샘플 데모를 `생성 전`, `생성 후`, `검수 후`, `전파 후`, `증빙 파일철` 흐름으로 재구성
- 라이브 API가 mock이면 데모 배지를 명확히 표시하거나 실제 API 모드 데모 환경을 별도 마련

산출물:

- 경쟁 대비 한 장 요약
- 심사용 데모 스크립트
- 라이브 스모크 결과

### Phase 1: 제출 전 검수 MVP

목표:

- SafeClaw의 첫 번째 고유 기능을 화면에서 체감하게 한다.

작업:

- `qa_review_docpack` 결과를 문서 화면 우측 패널로 표시
- 누락 조치, 근거 조문, 보완 문구를 문서별로 연결
- `validate_safety_citations`와 `sanitize_emergency_contacts`를 생성 후 자동 실행
- 검수 결과를 다운로드 문서 첫 장에 "제출 전 점검표"로 포함

산출물:

- 검수 패널 UI
- 검수 포함 문서팩 샘플
- 누락 탐지 테스트 케이스

### Phase 2: 증빙 파일철

목표:

- 중대재해처벌법 대응 문구를 추상 구호가 아니라 파일철 구조로 보여준다.

작업:

- `get_evidence_mapping` 결과를 `/evidence`와 `/archive`에 연결
- 문서팩별 증빙 목차 자동 생성
- 사진, 서명, 전파 로그가 없는 경우 보완 슬롯으로 표시
- PDF/HWPX/Excel 다운로드 시 증빙 목차 포함

산출물:

- 시행령 제4조 증빙 매핑 화면
- 파일철 다운로드 샘플
- 누락 슬롯 리포트

### Phase 3: 다국어 전파와 이해 확인

목표:

- 외국인 작업자 안내를 단순 번역에서 현장 확인 기록으로 확장한다.

작업:

- 작업자 언어 프로필과 문서팩 전파를 연결
- 쉬운 한국어 + 작업자 언어 안내문 생성
- 확인 링크 또는 간단 응답 수집
- TBM 문서에 이해 확인 결과 자동 반영

산출물:

- 다국어 전파 로그
- 작업자별 확인 상태
- TBM 반영 샘플

### Phase 4: SIF 기반 위험 분류

목표:

- 위험도 예측을 과장하지 않고, 고위험 작업의 검수 우선순위와 필수 조치 누락 탐지에 사용한다.

작업:

- 추락, 끼임, 감전, 화재, 폭발, 질식, 충돌, 열질환 등 SIF 분류 스키마 확정
- 작업 입력에서 SIF 후보를 자동 태깅
- SIF별 필수 확인 항목을 QA 검수 엔진에 연결
- SIF 태그별 문서팩 보완 문구 생성

산출물:

- SIF 스키마
- SIF별 필수 조치 테이블
- 물류/지게차, 건설/비계, 제조/화학물질 샘플

### Phase 5: 업종 특화

목표:

- 범용 서비스가 아니라 "한 업종에서는 바로 쓸 수 있는" 제품으로 만든다.

우선순위:

- 물류/지게차: 기존 데모와 고용24/기상/KOSHA 연결을 활용하기 좋다.
- 건설/비계: 심사 설득력은 높지만 경쟁자가 많아 제출 전 검수와 증빙 파일철을 같이 보여줘야 한다.
- 제조/화학물질: MSDS와 화학물질 규제가 들어가므로 별도 데이터 구조가 필요하다.

## 9. 바로 수정해야 할 제품 메시지

현재:

> 한 줄 입력으로 위험성평가, TBM, 안전교육, 외국인 안내문, 현장 전파 메시지 초안을 생성합니다.

개선:

> 한 줄 작업 입력을 위험성평가, TBM, 안전교육, 외국인 안내, 전파 로그, 제출 전 점검표가 묶인 안전 문서팩으로 정리합니다.

현재:

> 채용하지 않은 안전관리자 — 한 명 몫의 문서 업무를 대신합니다.

개선:

> 안전관리자가 놓치기 쉬운 근거, 누락 조치, 전파 증빙을 작업 전 한 번 더 확인합니다.

현재:

> 법령과 공식자료를 문서 문장에 연결합니다.

개선:

> 어떤 문장이 어떤 근거에서 왔는지 표시하고, 근거가 없거나 API가 실패한 항목은 숨기지 않고 보류 표시합니다.

## 10. 다음 구현 우선순위

1. 랜딩과 데모 스크립트에서 `생성 + 검수 + 전파 + 증빙` 루프를 전면화한다.
2. 라이브 `/api/ask` mock 상태를 심사용 데모에서 어떻게 설명할지 결정한다.
3. `qa_review_docpack` 결과를 실제 문서 UI에 붙인다.
4. 증빙 파일철 목차를 `/evidence`와 `/archive`에 연결한다.
5. 다국어 안내를 작업자 이해 확인과 전파 로그로 닫는다.
6. SIF 분류는 위험도 예측보다 QA 검수 우선순위에 먼저 붙인다.

## 11. 최종 제안

SafeClaw는 "AI가 안전문서를 써준다"는 말로는 경쟁력이 부족하다. 지금 당장 잡아야 할 한 문장은 다음이다.

> SafeClaw는 작업 전 안전문서를 생성하는 데서 멈추지 않고, 근거와 누락을 검수하고, 작업자 언어로 전파하고, 제출 가능한 증빙 파일철까지 남기는 안전문서 코파일럿입니다.

이 방향이면 멘토링에서 지적된 특장점 부재를 방어할 수 있고, 기존 코드베이스의 MCP, QA, evidence mapping, 다국어, archive 기능을 새로 갈아엎지 않고도 제품 차별점으로 재배치할 수 있다.
