# SafeClaw 검증 지도

이 폴더는 SafeClaw 의 사용자 관점 동작을 검증하는 유지 대상 정본이다. 앱을 구동하기 전에 이 색인을 읽고, 해당 기능 파일을 조리법으로 쓴다.

## 기본 전제

- 인스턴스는 `verify.mts drive` 가 띄운 격리 dev(`http://127.0.0.1:<20000~39999>`) 또는 `--base` 로 준 주소. 운영은 `https://www.safeclaw.kr`.
- 시드 없음. 모든 경로는 **익명(로그인 안 함)** 으로 시작한다 → 생성은 template 모드, 익명 안내 문장이 보인다.
- 합성 입력 한 줄: `경기 화성 물류창고 지게차 상하차 작업 4명, 비 예보, 야간`. 실명·주민번호·급여·사건 자료를 넣지 않는다.
- `doctor` 가 OK 가 아니면 구동하지 않는다. 이 실행이 띄우지 않은 인스턴스를 조작하지 않는다.

## 구동 규칙

- 선택자는 ARIA 라벨·`data-testid`·라우트·버튼 문구만. CSS 위치·좌표·탭 순서 금지.
- 생성 완료 신호 = `[aria-label="Safety Brief Dashboard"]` 가 보일 때. 고정 sleep 금지.
- 뷰포트 390×844 가 기본. 데스크톱(1440×900)은 기능 파일이 요구할 때만.
- 본문 텍스트에서 금지어(노무사·적중률·확률 N·AI/상주 안전관리자·전문가 자문)·`RA-<영문>-<숫자>`·대문자 enum 은 0. 진단·판정·상담·자문·대리는 문맥만 보고.

## 증명과 건너뜀 보고

- 행동 전·후 스크린샷, 내려받은 파일, 콘솔·페이지 오류 수를 `report.md` 에 남긴다.
- 변경(내려받기·인쇄)은 부수 효과(파일 크기·머리 바이트·`window.print` 호출 수)로 확인한다.
- 닿지 못한 입구는 시도한 명령과 충족 못 한 전제를 적는다. 다른 입구로 통과한 것을 그 입구의 검증으로 적지 않는다.

## 기능 파일 계약

H1 제목과 사용자에게 보이는 동작 한 문단, 그 뒤 H2 네 개를 이 순서로 둔다 — `Sub-features` · `How to get to it (user POV)` · `Driving it with verify.mts` · `Gotchas`. 구현 세부는 쓰지 않는다. 사용자 경로·안정 핸들·필요한 상태·명령·관찰 가능한 증거만.

## 기능

- [첫 화면 입력 폼](./home-composer.md) `home-composer` — 한 줄 입력 → 보내기 → `/workspace?q=` 즉시 생성, 익명 안내, 첫 화면 계약(지운 섹션 0·칩 3·금지어 0).
- [예시 칩](./example-chips.md) `example-chips` — 칩 3개 → `?scenario=&autogen=1` 무클릭 생성.
- [작업공간 결과](./workspace-result.md) `workspace-result` — 머리 「확인할 항목을 먼저 보세요」, 핵심 위험·위험성평가 상위, 문서 깊게 보기, 문서 조종석.
- [내보내기 4형식](./export-formats.md) `export-formats` — 편집기에서 xlsx·hwp 내려받기, PDF 인쇄 호출, HWPX 베타. inventory 의 「닫힘(운영) 미확인 = 내보내기 4형식」을 닫는 경로.
- [연차 일수 계산](./leave-tool.md) `leave-tool` — 명단 붙여넣기 → 자동 계산 표.

## 아직 지도가 없는 표면

`/tools/video-check`(동영상 위험 점검, 표본 영상 필요) · `/documents` 조종석 단독 화면 · `/share/[sessionId]` 수신자 화면(공유 세션 발급이 선행) · 외국인 전송본 미리보기·언어별 전송 차단 · 로그인·관리자 초대·full(AI) 생성(운영 금지, 인프로세스 시험 키 실행으로 대체) · `/knowledge`·`/evidence` 열람. 다음 UI PR 에서 닿는 것부터 추가한다.
