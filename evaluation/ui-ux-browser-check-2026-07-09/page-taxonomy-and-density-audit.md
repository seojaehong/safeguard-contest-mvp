# SafeClaw Page Taxonomy And Density Audit

Generated: 2026-07-09

## 기준 판단

워크스페이스는 현재 제품 톤의 기준 화면으로 둘 수 있다. 다만 워크스페이스도 아직 첫 화면에 너무 많은 축이 동시에 노출된다. 다른 페이지는 `SafeClawModuleShell`을 쓰더라도 대형 hero, 15개 사이드바 메뉴, 샘플 중심 모듈 때문에 워크스페이스와 같은 상업용 업무 도구처럼 읽히지 않는다.

따라서 다음 디자인 라운드는 색상 변경보다 정보구조 정리가 먼저다.

## 추천 최종 정보구조

앱 내부 1급 메뉴는 6개로 줄인다.

1. `작업공간` (`/workspace`)
   - 입력, 문서 생성, 공유까지 이어지는 기본 작업 흐름
   - 새 사용자의 첫 업무 화면

2. `문서` (`/documents`)
   - 현재 작업팩의 위험성평가표, TBM 브리핑, TBM 기록 편집
   - TBM 풀스크린은 이 안의 버튼으로 이동

3. `리포트` (`/reports`)
   - 오늘/주간/월간 개선 리포트
   - 개선사항 As-Is/To-Be, 공정별/작업별/위험등급별 다운로드

4. `근거` (`/evidence`)
   - SIF/KOSHA/법령/문서 반영 위치
   - `knowledge`, `ontology`는 이 화면의 하위 탭 또는 상세 화면

5. `이력` (`/archive`)
   - 작업팩 이력, 개선 이력, 확인 이력
   - `evidence-file`은 이력 안의 증빙 패키지로 흡수

6. `설정` (`/settings`)
   - AI 연결, OpenClaw/OpenAI OAuth, API 연결, 운영 설정
   - `settings/ai-connect`, `ops/api`, `dryrun`은 설정 하위 화면

외부/공개 화면은 앱 사이드바에서 분리한다.

- `/`: 공개 홈페이지
- `/why`, `/trust`, `/roadmap`: 공개 설명/신뢰/로드맵
- `/login`: 진입/로그인
- `/worker`: 작업자 열람 전용 링크 화면

데모/레거시/개발 화면은 기본 메뉴에서 숨긴다.

- `/demo`, `/prototype`, `/preview`, `/ask`, `/search`
- `/law/[id]`, `/precedent/[id]`, `/interpretation/[id]`는 근거 상세 링크로만 접근

## Workspace Density Cuts

워크스페이스는 유지하되 첫 입력 화면은 더 줄인다.

### 첫 화면에 남길 것

- SafeClaw 로고/현재 단계/Day Night toggle
- 작은 제목: `오늘 작업은 무엇인가요?`
- 입력창
- 자동 인식 칩 최대 3개: 지역, 작업, 인원/날씨 중 핵심
- `+ 첨부` 버튼: 사진부터 시작하고, 장기적으로 PDF/HWPX/Excel/도면 파일까지 같은 진입점 사용
- primary CTA 하나: `안전 문서 생성`

### Composer Attachment Pattern

사진은 별도 메뉴나 별도 카드가 아니라 입력창 안의 `+` 첨부 액션으로 들어간다. 사용자는 작업 설명을 쓰다가 사진을 붙이고, SafeClaw는 첨부될 때마다 조용히 위험요인 후보를 분석한다.

권장 흐름:

1. 사용자가 입력창의 `+`를 누른다.
2. `사진 첨부`, `파일 첨부`, `최근 자료` 메뉴가 열린다. 1차는 사진만 활성화하고 파일은 `준비 중`이 아니라 숨기거나 비활성 tooltip 처리한다.
3. 사진을 1~10장 첨부하면 썸네일 chip이 입력창 하단에 붙는다.
4. vision/OCR 분석은 자동으로 시작한다. 분석 중에는 `사진 3장 분석 중` 정도의 작은 상태만 보인다.
5. 후보가 나오면 입력창 아래에 `위험 후보` chip/card가 최대 3개만 뜬다.
6. 각 후보는 `추가`, `무시`, `자세히` 세 행동만 가진다.
7. `추가`를 누르면 입력 텍스트에 길게 붙이지 말고, 별도 `acceptedPhotoHazards` 상태로 보관한 뒤 생성 요청 payload에 함께 보낸다.
8. 문서 단계에서 “사진에서 반영된 위험요인”으로 근거/품질 패널에 표시한다.

장기 파일 첨부도 같은 패턴을 쓴다.

- 사진: vision/OCR로 위험요인 후보 추출
- PDF/HWPX: OCR/문서 파싱으로 현장명, 작업명, 기존 위험성평가 행 추출
- Excel: 위험성평가 표 행 import 후보 추출
- 도면/이미지: 구역명, 통로, 개구부, 장비 배치 후보 추출

핵심은 “첨부가 새 메뉴가 되는 것”이 아니라 “입력의 보조 맥락이 되는 것”이다.

### 접거나 뒤로 보낼 것

- `근거 준비` 4개 레일: 한 줄 `근거 4종 준비 중`으로 축소, 세부는 문서 단계에서 펼침
- 사진 위험요인 분석 카드: 입력창 `+ 첨부` drawer와 후보 chip으로 흡수
- 최근 예시 목록: 좌측 rail에서 `최근 작업` drawer로 접기
- 고급 설정: 기본 접힘 유지, 첫 화면 card로 보이지 않게 하기
- 현재 작업 요약: workpack이 있을 때만 표시. 새 입력 화면에서는 숨김
- 생성 console: 기본 숨김. 실패가 아니라 `검토 필요 항목`만 노출

### 문서 단계에 둘 것

- SIF/KOSHA/법령 인용 자료
- 품질/누락 조치 패널
- 3개 핵심 문서: 위험성평가표, TBM 브리핑, TBM 기록
- `+ 더 보기`로 보조 문서

### 공유 단계에 둘 것

- 대상/권한/언어
- 확인 현황
- 저장될 이력
- 작업자 열람 링크

## Shell Direction

현재 `SafeClawModuleShell`은 메뉴가 15개라 정보구조 자체가 무겁다. 새 공통 shell은 워크스페이스 톤을 기준으로 한다.

- 사이드바 6개 메뉴 이하
- 대형 hero 제거
- 페이지별 제목은 compact document header로 축소
- 모든 앱 페이지는 카드보다 문서/패널 구조
- `sample`, `demo`, `planned`, `mock` 같은 visible tone 제거
- 공개 페이지는 별도 marketing shell 유지

## Implementation Proposal

승인 후 작업 순서는 다음이 적절하다.

1. `SafeClawModuleShell` 메뉴를 6개로 줄이고 숨김 route를 명시한다.
2. `/documents`, `/reports`, `/evidence`, `/archive`, `/settings`를 워크스페이스 톤으로 맞춘다.
3. `/workers`, `/dispatch`, `/tbm`, `/knowledge`, `/ontology`, `/ops/api`, `/settings/ai-connect`는 하위 탭/링크로 재배치한다.
4. `/workspace` input 화면에서 근거 레일, 사진 카드, 최근 예시, 고급 설정 노출을 축소한다.
5. Playwright로 desktop/mobile 캡처를 만들고, 첫 화면에 사용자 결정 지점이 하나인지 확인한다.

## Recommendation

정답은 “워크스페이스만 예쁘게 두고 나머지를 맞추기”가 아니라, 워크스페이스도 조금 더 덜어내면서 전체 앱을 6개 업무 메뉴로 재분류하는 것이다. SafeClaw의 제품 차별점은 많은 메뉴가 아니라 `작업 입력 -> 문서 -> 공유 -> 개선 이력 회수` 루프다.
