# Document Editor Design Follow-up

Date: 2026-07-10 KST
Branch: `feature/backend-harness-gate`

## Issue

The workspace itself had moved toward the Linear-style workbench, but the document edit/export surface could still expose older submission-form styling:

- heavy black section labels
- beige table headers
- thick black grid borders
- document-type color blocks

That made the flow feel like it reverted to an earlier UI after clicking edit or opening a document output preview.

## Change

- Kept the document editor inside the current light workspace design system.
- Updated the in-app submission preview table treatment:
  - neutral hairline table wrapper
  - rounded section labels
  - neutral header rows
  - no heavy black section label treatment
- Updated exported HTML/PDF/JPG document CSS generated by `formCss()`:
  - canvas `#FAFAFB`
  - page surface `#FFFFFF`
  - hairline `#E6E8EB`
  - neutral section chips and table headers
  - removed old `#161b22`, `#f2ead9`, and document-type dark blocks from the generated form CSS
- Added regression coverage so the old visual language does not return through the HTML export path.
