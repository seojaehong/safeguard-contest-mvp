# Documents table is exposed without row-level security

## Summary

documents is created without row-level security, allowing unauthorized read or mutation of stored document content under Supabase default grants. Browser Supabase configuration proves intended direct REST capability and canonical migrations never add documents RLS; live table grants/existence remain unverified and were not changed.

## Root Cause

The violated invariant is that documents table is exposed without row-level security. Current source instead shows: The table contains title, summary, body, citation, and source_url, but this migration has no RLS enablement or policy for documents and no assigned later migration adds one.

### Root Control evidence

`supabase/migrations/001_init.sql:8-16`

```sql
create table if not exists documents (
  id text primary key,
  doc_type text not null,
  title text not null,
  summary text,
  body text,
  citation text,
  source_url text,
  created_at timestamptz not null default now()
```

This root_control location carries or governs the validated path: The table contains title, summary, body, citation, and source_url, but this migration has no RLS enablement or policy for documents and no assigned later migration adds one.

## Validation

Method: Cumulative canonical migration and browser-client exposure trace

documents contains sensitive bodies/citations; migration 001 never enables RLS and no later migration or grant revocation closes direct access.

Limitations:

## Dataflow

Direct Supabase PostgREST anon/authenticated request -> public.documents created without RLS/policy/grant revocation -> select/insert/update/delete -> document body, citation, and source content disclosure or mutation.

## Reachability

Browser Supabase configuration proves intended direct REST capability and canonical migrations never add documents RLS; live table grants/existence remain unverified and were not changed.

Counterevidence: No application route is required and service-role checks cannot protect direct REST. Missing live catalog proof lowers likelihood confidence but is not source-level suppression.

## Severity

**medium**. The matrix maps high impact and unknown likelihood to medium because broad document confidentiality/integrity loss is credible under normal grants, while live grants and migration state are unverified.

Change conditions: Raise likelihood if live anon/authenticated grants and populated rows are confirmed; ignore if verified live grants revoke direct access or the table is absent/protected by a later policy.

## Remediation

Enable RLS, define explicit least-privilege select and mutation policies, bind rows to immutable tenant ownership, and revoke broad grants not required by the product.

Regression tests:
- Anonymous and unrelated authenticated roles cannot read or mutate documents.
- Tenant A cannot access tenant B document bodies or citations.
