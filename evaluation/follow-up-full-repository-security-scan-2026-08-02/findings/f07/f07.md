## Summary

education_records RLS does not require site_id, workpack_id, or worker_id to belong to the authorized organization. Browser Supabase clients and canonical owner policies support direct authenticated REST as a distinct path from service-role application access; exploitation requires a valid account and foreign UUID. ## Root Cause

The violated invariant is that education records can bind cross-tenant work objects. Current source instead shows: The child row has three independently supplied foreign keys, but USING/WITH CHECK validate only education_records.organization_id, enabling forged cross-tenant training relationships when an identifier is known.

      where organizations.id = education_records.organization_id
