## Summary

dispatch_logs policy explicitly allows rows with null organization_id, bypassing tenant authorization for reads and writes. Canonical migration policy is directly applicable to browser Supabase roles when deployed; browser URL/anon-key configuration proves intended direct REST capability, but live grants and migration state were not mutated or verified.

## Root Cause

The violated invariant is that null dispatch-log tenants bypass row-level authorization. Current source instead shows: Both USING and WITH CHECK begin with organization_id is null, so the policy succeeds without auth.uid ownership and exposes nullable contact, provider status, failure, and payload fields through direct table access.

### Root Control evidence

`supabase/migrations/002_workspace_productization.sql:183-199`

```sql
create policy "owners can manage dispatch logs"
  on dispatch_logs for all
  using (
    organization_id is null
    or exists (
      select 1 from organizations
      where organizations.id = dispatch_logs.organization_id
        and organizations.owner_id = auth.uid()
    )
  )
  with check (
    organization_id is null
    or exists (
      select 1 from organizations
      where organizations.id = dispatch_logs.organization_id
        and organizations.owner_id = auth.uid()
    )
```
