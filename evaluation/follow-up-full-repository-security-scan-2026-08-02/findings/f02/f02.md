# MCP document generation accepts unbounded authenticated inputs

| Field | Value |
| --- | --- |
| Severity | low |
| Confidence | high |
| Category | Resource exhaustion |
| CWE | CWE-400 |

## Summary

MCP generation tools accept unbounded strings before long-running AI and QA work. Remote MCP transport is repository-defined and bearer-authenticated; a valid low-trust scoped token can invoke up to 300-second work, while the 20/min limiter is warm-instance-local and no per-request byte budget exists.

## Root Cause

The violated invariant is that mcp document generation accepts unbounded authenticated inputs. Current source instead shows: generate_reviewed_safety_docpack and generate_safety_docpack define question/task as plain z.string() without max lengths and delegate to full runAsk generation; the transport permits 20 POSTs per token per minute and a 300-second handler duration, but provides no request-body or per-field size budget.

## Validation

Method: Static authenticated MCP source/control/sink trace across schemas, auth, handlers, AI generation, QA, and persistence

Authentication and a soft per-token rate limit exist, but unbounded strings reach expensive generation before any character/body budget.

Limitations:
- Auth and rate limiting reduce anonymous abuse but do not bound per-request work.
- Deployment-level request-body limits and distributed quotas are not evidenced in repo.

## Dataflow

Authenticated scoped MCP tool strings/includeFull -> unbounded z.string schemas -> knowledge search and runAsk/provider generation -> QA -> optional tenant persistence and response assembly.

## Reachability

Remote MCP transport is repository-defined and bearer-authenticated; a valid low-trust scoped token can invoke up to 300-second work, while the 20/min limiter is warm-instance-local and no per-request byte budget exists.

Counterevidence: Bearer authentication, scopes, disabled-when-unconfigured behavior, and a soft rate limiter reduce exposure; they do not bound one accepted request or distributed token use.

## Severity

**low**. The matrix maps medium impact and medium likelihood to low because valid token possession and existing throttling constrain otherwise expensive work.

Change conditions: Raise if modest authenticated traffic is proven to create sustained shared outage or material provider cost; ignore if platform and distributed quotas enforce effective body, work, and response budgets.

## Remediation

Apply shared byte and character budgets to every MCP generation field before AI or QA work, cap aggregate tool payloads, and use a durable tenant-aware rate limit for costly operations.

Regression tests:
- Reject over-budget strings before invoking any provider or persistence helper.
- Assert aggregate nested payload limits and durable tenant throttling.
