## Summary

workpacks RLS permits cross-tenant site_id associations because the policy checks only organization ownership. Browser Supabase clients and canonical owner policies support direct authenticated REST as a distinct path from service-role application access; exploitation requires a valid account and foreign UUID. Live policy/application state is unverified without approval.

## Root Cause

The violated invariant is that workpacks can reference another tenant's site. Current source instead shows: A workpack can carry any existing site_id FK while WITH CHECK validates only workpacks.organization_id against an organization owned by auth.uid().

### Root Control evidence

`supabase/migrations/002_workspace_productization.sql:149-164`

```sql
create policy "owners can manage workpacks"
  on workpacks for all
  using (
    exists (
      select 1 from organizations
      where organizations.id = workpacks.organization_id
        and organizations.owner_id = auth.uid()
    )
  )
  with check (
    exists (
      select 1 from organizations
      where organizations.id = workpacks.organization_id
        and organizations.owner_id = auth.uid()
    )
```

## Remediation

Regression tests:
