## North Star 시험과 편집 흐름

위험행 편집기는4개 textarea를 한꺼번에 띄우는 구조에서, 여러 위험행 선택 버튼과 한 개의 활성 편집 패널로 바뀌었다. 단순히 옛 단언을 지우지 않고 위험요인 수정→다른 행→마지막 행→첫 행의 값 유지까지 확인한다.

측정은 활성 문서 편집 화면으로 한정하며, 닫힌 details·스크롤로 완전히 가려진 요소를 보이는 것으로 세지 않는다. 가로 스크롤 포트의 일부만 보이는 선택 버튼과 스크롤 불가능한 영역의 잘림도 축별로 구분한다. 편집기의80/240ms 정렬과 글꼴 로드가 끝나고 위치가 안정된 뒤 측정한다.

실제 중첩 세로 스크롤도 재현됐다. 작업공간의 외곽 편집영역이 스크롤을 맡고 안쪽 grid·문서 열은 추가 스크롤을 만들지 않도록 바꿨다. 기존 Night 계약도 새 스크롤 소유 관계에 맞췄으며 외곽 영역의 경계·스크롤 가능 검사는 유지한다. 포커스 이동으로 overflow:hidden인 바깥 viewport가 따로 스크롤돼 버튼을 자르던 문제는, 편집 포커스에서 가로 clip·세로 visible로 보완한다.

## 증거의 신선도와 거짓 통과 방지

- CSS 모듈을 화면 지문에서 빠뜨리던 빈틈을 보완했다. app·components의 TSX와 CSS를 함께 지문에 넣고 CSS 변조 시 지문이 달라지는 실패 시험을 확인했다.
- 타입스크립트 정본 리터럴 읽기는 공용 분류기에서 재사용한다. 감사기의 글꼴·제목·모서리 기대값을 실제 관측값에 맞춰 자동 채택하지 않는다.
- 잘못된 글꼴, 미로드 글꼴, 틀린 제목 튜플,30px 높이,6/8px 모서리, HTTP·경로·경계 오류를 거절하는 시험을 유지한다.
- 일반/감사 빌드를 전환할 때 이전 모드의 청크가 남는 것을 확인했다. 기존 clean build 도구로 다시 빌드하고 일반 번들에서 감사 코드가 빠졌는지 확인한다.
- 과거322건 원시 보고서와 예비 실패 실측은 이력으로 보존한다. 최종 결과는 이 폴더의 새 browser-report.json과 CI 실행 원문을 기준으로 한다.
